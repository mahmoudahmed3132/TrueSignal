## 1. What TrueSignal is (one paragraph)

A fork of HoneyWire v2.1.0 (AGPLv3, Andrea Termine), fully rebranded to TrueSignal. Docker-based deception platform: a Go **Hub** (chi router, modernc SQLite WAL, embedded Vue 3 UI) that catalogs sensors, compiles per-node docker-compose, receives events, and routes them to the UI (WebSocket), webhooks (ntfy/gotify/discord/slack) and syslog. **Sensors** are containerized decoys deployed to nodes by a root CLI **Wizard** (`truesignal`). Go + Python SDKs. Detection logic lives in sensors; the Hub is the only policy authority and treats sensors/manifests/wizard as untrusted. Distribution targets the owner's GitHub + ghcr (nothing published yet; repo private → anonymous pulls fail, unresolved owner decision). ## 3. Identity Decoy sensor — current state (the active work area)

Path: `Sensors/official/IdentityDecoy/`. One container serves multiple ports from `TS_SERVICES` (default `ldap:389,ldaps:636,rdp:3389`). Files:
- `main.go` — env parsing, service dispatch, persona, TLS config (built if ldaps OR rdp-with-NLA), `serveFunc`, `reporter` interface (so handlers are unit-testable with a fake), `parseServices` (validates proto∈{ldap,ldaps,rdp}, port range, dup port within sensor).
- `credcapture.go` — keyed-HMAC credential policy (`TS_CAPTURE_PASSWORDS=hash|plain|none`, `TS_CAPTURE_HASH_KEY`; default derives key from node key). `secret(prefix,val)` / `password(val)`.
- `ldap.go` — minimal BER reader/writer (`berReader`, `berTLV`, `berInt`, `readTLV`, `concat` — **reused by credssp.go**). Serves bind + search. Simple bind → `ldap_login`/`ldaps_login` (critical) with bind DN, AD-style `data 52e` failure reply; anonymous bind + search → `*_query` (medium) over an empty non-erroring directory. `*_connection` (low).
- `rdp.go` — X.224 CR parse → mstshash cookie (`rdp_login`, auth `mstshash`). If client requests NLA (HYBRID) and `TS_CAPTURE_NTLM!=off`: select HYBRID, TLS handshake (in-memory cert), CredSSP/NTLM exchange, capture `DOMAIN\user`+workstation (`rdp_login`, auth `nla_ntlm`), reply logon-failure NTSTATUS. `readTSRequest` reads one DER frame bounded.
- `ntlm.go` — NTLM Type 2 build (challenge + persona TargetInfo), Type 3 parse (user/domain/workstation/NtResponse), `netNTLMv2` hashcat-5600 formatter, `netbios()`, utf16 helpers. Re-derived from MS-NLMP; no third-party code.
- `credssp.go` — TSRequest DER encode/decode (`ctx(n,inner)`=context tag), SPNEGO detection + wrapping, `parseTSRequest` locates NTLMSSP signature, `buildChallengeTSRequest`, `buildErrorTSRequest`.
- `tlsgen.go` — in-memory self-signed cert (persona CN); container is read-only so no disk.
- `identity-decoy.json` — manifest. version `2.0.0` (**major must == Hub major 2**, this bit me — a `1.0.0` manifest is filtered out as incompatible). `network_mode host`, `user 0:0`, `cap_add [NET_BIND_SERVICE]`, `listen_ports_env [TS_SERVICES]`. Env: standard 5 + `TS_SERVICES`, `TS_PERSONA_HOSTNAME` (DC01), `TS_PERSONA_DOMAIN` (corp.local), `TS_CAPTURE_PASSWORDS`, `TS_CAPTURE_HASH_KEY`, `TS_CAPTURE_NTLM` (identity|hash|off). image `ghcr.io/mahmoudahmed3132/truesignal-identitydecoy`.
- `main_test.go`, `nla_test.go` — unit + full TLS/CredSSP flow tests with a `fakeReporter`.

**Capture policy (important, PCI):** passwords → keyed HMAC by default. RDP NLA: `TS_CAPTURE_NTLM=identity` (default) records only `DOMAIN\user`+workstation (no crackable material); `hash` also stores the NetNTLMv2 (hashcat 5600) for threat intel — keep out of PCI scope; `off` = mstshash only.

Event triggers emitted: `ldap_login`, `ldaps_login`, `rdp_login` (critical); `ldap_query`, `ldaps_query` (medium); `ldap_connection`, `ldaps_connection`, `rdp_connection` (low).

**Deferred (next increments):**
1. **LDAP SASL/NTLM bind capture** — BloodHound and many Windows tools bind via SASL/NTLM, not simple bind; currently only simple bind is captured. Trapster's `libs/ntlm.py` + `ldap.py` sicilyNegotiate/sasl paths are the reference. The NTLM helpers now exist in `ntlm.go` to reuse.
2. **ECS SIEM output** — add an ECS JSON format option to the Hub SIEM service (`siem_format: rfc5424|ecs`) + an HTTP output (LogScale HEC / Elastic bulk). Maps to user's Elastic + LogScale. Trapster's `logger/ecs.py` + `formatters.py` is a reference for the ECS field mapping.
3. **Honeytoken link** — Hub registry of fake credentials; File Canary plants them in lures; service decoys compare captured logins against the registry by keyed hash; a match raises critical `honeytoken_used` naming the lure (highest-confidence deception signal). This is net-new vs Trapster.
4. Further Trapster ports as more multi-port sensors: `DatabaseDecoy` (MySQL/MSSQL/Postgres), `RemoteAccessDecoy` (SSH/Telnet/VNC/FTP/Rsync), `NetworkServiceDecoy` (SNMP, log-only DNS — do NOT forward DNS like Trapster does; that's an open-resolver risk). Also an HTTP skin engine to replace the single hardcoded Web Router Decoy page.

**Do NOT adopt from Trapster:** AI-generated SSH/HTTP responses (fingerprintable, sends data to external LLM — CDE data egress); DNS forwarding as written (open resolver / internal DNS leak); Redis output; SOCKS5 (dead code there).

## 4. Testing conventions (match these)

For each sensor/Hub change, this session always did:
1. `gofmt -l` clean (struct-field alignment often needs `gofmt -w` after adding a field).
2. `go vet ./...` + `go test -race ./...` per affected module.
3. UI: `cd Hub/ui && npm run build` (vue-tsc) when UI or Hub-embedding touched.
4. **Live E2E** against a real Hub binary + real sensor binaries + a local static registry (`scratchpad/e2e/`): boot Hub (dev, `TS_SETUP_TOKEN`), create node, add sensor, fetch compose, run sensor binary, drive it with real protocol clients, assert events landed in the Hub SQLite. Also `docker compose config -q` on generated compose, and Trivy fs (checksum-verified binary) for dep CVEs.
5. Watch out for test-harness escaping bugs when asserting on JSON strings pulled from SQLite (backslashes double-escape; compare parsed dicts, not `json.dumps` substrings).
6. Add the new module to `.github/workflows/test.yml` matrix.
7. Never commit the built sensor binary — it's gitignored per-sensor (`.gitignore` has `/Sensors/official/<Name>/<lowercasebinary>`). `go build ./...` drops one in the dir; check `git ls-files` before/after.

Hub major version constant: `HubVersion = "2.1.0"` in `Hub/internal/models/models.go`. Sensor manifests must have matching **major** (2.x).
